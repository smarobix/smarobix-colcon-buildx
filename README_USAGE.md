# Build Script Usage Guide

## Quick Start

### Prerequisites

1. **Pull the Docker image from GitLab registry:**
   ```bash
   docker pull --platform linux/arm64 git.smarobox.de:5050/smarobix/automatica-2025/kria_ros_cross_compile:jazzy-base
   ```

2. **Enable ARM64 emulation (if on x86_64):**
   ```bash
   docker run --rm --privileged multiarch/qemu-user-static --reset -p yes
   ```

### Basic Usage

**From the workspace root OR the kria_ros_cross_compile directory:**

```bash
# Test build locally (no deployment)
./kria_ros_cross_compile/build_persistent.sh --dry-run

# Build and sync to Kria board
./kria_ros_cross_compile/build_persistent.sh --sync-to kria-robotics:~/ros2_ws/install/

# Subsequent incremental builds
./kria_ros_cross_compile/build_persistent.sh --sync-to kria-robotics:~/ros2_ws/install/
```

## Understanding the Workspace Structure

```
ros2_ws/                              # Workspace root (auto-detected)
├── src/                             # Your ROS 2 packages
│   ├── axi_dma_cpp/
│   ├── object_tracking_demo/
│   ├── object_tracking_fpga/
│   ├── object_tracking_msgs/
│   └── ...
├── kria_products/                   # Generated by script
│   └── install/                    # Built packages ready to deploy
└── kria_ros_cross_compile/         # Build tools
    ├── build_persistent.sh         # Main build script
    ├── BUILD_OPTIMIZATION.md
    └── README_USAGE.md (this file)
```

**How it works:**
1. Script auto-detects workspace root (parent of `src/`)
2. Mounts `src/` as read-only in Docker container
3. Builds using persistent Docker volumes for speed
4. Extracts `install/` folder to `kria_products/`
5. Optionally syncs to remote target via rsync

## Key Concepts

### 1. Docker Image = ROS Distribution

The ROS distribution (Jazzy, Humble, etc.) is **baked into the Docker image**. You cannot change it with a flag.

- `jazzy-base` → Contains ROS 2 Jazzy
- `humble-base` → Contains ROS 2 Humble

To use a different ROS version, use a different image:
```bash
./build_persistent.sh --image git.smarobox.de:5050/.../humble-base --dry-run
```

The script auto-detects the ROS distribution from the image name.

### 2. Workspace Location is Auto-Detected

You don't need to specify where your workspace is. The script:
1. Finds its own location
2. Goes up one directory to find workspace root
3. Validates that `src/` exists
4. Mounts the correct paths to Docker

### 3. Dry Run vs Sync

**Dry Run Mode** (`--dry-run`):
- Builds all packages
- Extracts to `kria_products/install/`
- Does NOT sync to remote
- Use for testing or deploying to multiple targets

**Sync Mode** (`--sync-to <target>`):
- Builds all packages
- Extracts to `kria_products/install/`
- Automatically syncs to specified remote target via rsync

## Common Workflows

### Development Workflow

```bash
# 1. Make code changes in src/

# 2. Test build locally
cd ros2_ws  # or cd ros2_ws/kria_ros_cross_compile
./kria_ros_cross_compile/build_persistent.sh --dry-run

# 3. If successful, sync to Kria
./kria_ros_cross_compile/build_persistent.sh --sync-to kria-robotics:~/ros2_ws/install/

# 4. SSH to Kria and test
ssh kria-robotics
source ~/ros2_ws/install/setup.bash
ros2 launch object_tracking_demo demo_launch.py
```

### Building Specific Packages

```bash
# Build only one package
./build_persistent.sh --dry-run --packages-select object_tracking_demo

# Build up to a package (includes dependencies)
./build_persistent.sh --dry-run --packages-up-to object_tracking_fpga

# Skip visualization (no GUI needed on Kria)
./build_persistent.sh --sync-to kria-robotics:~/ros2_ws/install/ \
  --packages-skip object_tracking_visualization
```

### Deploying to Multiple Boards

```bash
# Build once
./build_persistent.sh --dry-run

# Deploy to multiple Kria boards
rsync -avz ./kria_products/install/ kria-board-1:~/ros2_ws/install/
rsync -avz ./kria_products/install/ kria-board-2:~/ros2_ws/install/
rsync -avz ./kria_products/install/ kria-board-3:~/ros2_ws/install/
```

### Clean Builds

```bash
# Clean and rebuild
./build_persistent.sh --clean --dry-run

# Force container rebuild (if image updated)
./build_persistent.sh --rebuild-container --dry-run
```

## Troubleshooting

### "Error: Source directory not found"

**Cause:** Script can't find the workspace `src/` folder.

**Solution:** Run from either workspace root or `kria_ros_cross_compile/`:
```bash
cd /path/to/ros2_ws
./kria_ros_cross_compile/build_persistent.sh --help
```

### "exec format error" when starting container

**Cause:** ARM64 emulation not enabled on x86_64 host.

**Solution:**
```bash
docker run --rm --privileged multiarch/qemu-user-static --reset -p yes
```

### Build is slow / not incremental

**Cause:** Container was removed, losing cached builds.

**Solution:** Don't use `--rebuild-container` unless necessary. The persistent volumes retain build cache between runs.

### Can't connect to GitLab registry

**Cause:** Authentication required.

**Solution:**
```bash
echo $GITLAB_TOKEN | docker login git.smarobox.de:5050 -u <username> --password-stdin
docker pull --platform linux/arm64 git.smarobox.de:5050/.../jazzy-base
```

## Advanced Options

### Using Custom Images

```bash
# Use specific commit SHA
./build_persistent.sh \
  --image git.smarobox.de:5050/.../jazzy-base-abc1234 \
  --dry-run

# Use locally built image
./build_persistent.sh --image my-test-image:latest --dry-run
```

### Container Management

```bash
# Check if container is running
docker ps -f name=ros2-kria-builder

# Stop container (preserves volumes)
docker stop ros2-kria-builder

# Remove container (keeps volumes for next run)
docker rm ros2-kria-builder

# Remove everything and start fresh
docker rm -f ros2-kria-builder
docker volume rm ros2_kria_build ros2_kria_install
```

### Inspecting Build Artifacts

```bash
# Access the build container
docker exec -it ros2-kria-builder bash

# Inside container:
source /opt/ros/jazzy/setup.bash
colcon list
ls -la build/
ls -la install/
```
